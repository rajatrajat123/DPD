# Aura Platform — REST & WebSocket API Contracts (`API_CONTRACTS.md`)

**Base Path**: `/api/v1`  
**Content-Type**: `application/json; charset=utf-8`  
**Authentication**: `Authorization: Bearer <JWT_ACCESS_TOKEN>` (or `HttpOnly; Secure; SameSite=Lax` cookie for Web SSR)

---

## 1. Standard Envelopes, Headers & Error Format

### 1.1 Standard Request & Response Headers
- `X-Request-ID`: UUID v4 generated by client or injected by Go middleware; echoed on every response and logged in structured telemetry.
- `Idempotency-Key`: Required on state-mutating payment, swipe, media upload completion, and payout endpoints.

### 1.2 Standardized Error Response (`internal/apperror`)
All 4xx and 5xx responses return a deterministic JSON structure:

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "Request payload failed validation",
    "request_id": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d",
    "timestamp": "2026-10-13T02:00:00Z",
    "fields": {
      "birthdate": "Member must be at least 18 years old"
    }
  }
}
```

| HTTP Status | Error Code | Meaning |
| :--- | :--- | :--- |
| `400 Bad Request` | `INVALID_REQUEST` / `VALIDATION_FAILED` | Malformed JSON or failed field constraints |
| `401 Unauthorized` | `UNAUTHENTICATED` / `TOKEN_EXPIRED` | Missing, expired, or invalid JWT access token |
| `403 Forbidden` | `FORBIDDEN` / `ENTITLEMENT_REQUIRED` | Insufficient role or paid tier required |
| `404 Not Found` | `RESOURCE_NOT_FOUND` | Entity does not exist or is hidden by privacy rules |
| `409 Conflict` | `CONFLICT` / `IDEMPOTENCY_CONFLICT` | Duplicate resource or concurrent state conflict |
| `422 Unprocessable Entity` | `BUSINESS_RULE_VIOLATION` | Semantic domain rule violation (e.g., quota exhausted) |
| `429 Too Many Requests` | `RATE_LIMIT_EXCEEDED` | Redis token-bucket rate limit exceeded |
| `503 Service Unavailable` | `DEPENDENCY_UNAVAILABLE` | Downstream dependency (Postgres/Redis) not ready |

## 2. System Health & Readiness Endpoints (Implemented in Phase 01)

### `GET /healthz` and `GET /api/v1/healthz`
Liveness probe verifying the Go HTTP server process is responsive.
```json
{
  "status": "alive",
  "service": "aura-backend-api",
  "version": "0.1.0",
  "timestamp": "2026-10-13T02:00:00Z"
}
```

### `GET /readyz` and `GET /api/v1/readyz`
Readiness probe verifying active connectivity to PostgreSQL (+ PostGIS extension) and Redis. Returns `200 OK` when all dependencies are healthy, or `503 Service Unavailable` with diagnostic breakdown when degraded.
```json
{
  "status": "ready",
  "service": "aura-backend-api",
  "checks": {
    "postgres": { "status": "up", "latency_ms": 2 },
    "redis": { "status": "up", "latency_ms": 1 }
  },
  "timestamp": "2026-10-13T02:00:00Z"
}
```

## 3. Domain API Endpoints

### 3.1 Identity & Authentication (`/api/v1/auth`)
- `POST /api/v1/auth/register` — Create account with email/phone, Argon2id password, age verification ($\ge 18$), and optional `referral_code`.
- `POST /api/v1/auth/login` — Authenticate credentials; returns short-lived `access_token` (`15m`) and rotating `refresh_token` (`30d`).
- `POST /api/v1/auth/oauth/{provider}` — Exchange Apple / Google OIDC authorization code.
- `POST /api/v1/auth/refresh` — Rotate refresh token and issue new access token.
- `POST /api/v1/auth/logout` — Revoke current session refresh token in PostgreSQL & Redis blocklist.
- `POST /api/v1/auth/otp/send` & `POST /api/v1/auth/otp/verify` — Phone SMS verification.

### 3.2 Profiles, LGBTQ+ Taxonomy & Preferences (`/api/v1/profiles`)
- `GET /api/v1/profiles/me` — Fetch full authenticated member profile, verification status, and active entitlements.
- `PUT /api/v1/profiles/me` — Update display name, bio, pronouns, gender identities, sexual orientations, relationship intents, and per-field visibility rules.
- `PUT /api/v1/profiles/me/preferences` — Update discovery filters (age range, distance radius km, preferred genders, preferred intents, verified-only toggle).
- `PUT /api/v1/profiles/me/location` — Submit device latitude/longitude; server updates PostGIS `GEOGRAPHY(Point, 4326)` and returns only city name and fuzzed region.

### 3.3 Media Upload & Processing Pipeline (`/api/v1/media`)
- `POST /api/v1/media/upload-intent`
  - **Request**: `{ "media_type": "IMAGE", "mime_type": "image/jpeg", "size_bytes": 3421000, "purpose": "PROFILE_GALLERY", "idempotency_key": "..." }`
  - **Response (`201 Created`)**: `{ "media_id": "uuid", "upload_url": "https://...", "expires_at": "...", "status": "PENDING_UPLOAD" }`
- `POST /api/v1/media/{id}/complete`
  - Signals upload completion; enqueues asynchronous EXIF stripping, moderation, and WebP/AVIF/FFmpeg transcoding job. Returns `202 Accepted` (`status: "PROCESSING"`).
- `GET /api/v1/media/{id}/status`
  - Polls processing state (`PROCESSING`, `MODERATION_PENDING`, `READY`, `REJECTED`) and returns signed CDN derivative URLs (`thumb_webp`, `card_webp`, `full_avif`, `hls_playlist`) only when `status == "READY"`.
- `DELETE /api/v1/media/{id}` — Removes media from profile and schedules storage deletion.

### 3.4 Discovery, Swipes, Matching & Boosts (`/api/v1/discovery`, `/api/v1/swipes`, `/api/v1/matches`)
- `GET /api/v1/discovery/feed?limit=20&cursor=...`
  - Returns ranked candidate profiles within PostGIS radius. Coordinates are stripped; each candidate includes `distance_bucket_km` (fuzzed) and signed derivative media URLs.
- `POST /api/v1/swipes`
  - **Request**: `{ "target_user_id": "uuid", "direction": "LIKE" | "PASS" | "SUPER_SPARK", "intro_note": "..." }`
  - **Response**: `{ "swipe_id": "uuid", "is_mutual_match": true, "match_id": "uuid", "conversation_id": "uuid", "remaining_likes_today": 14 }`
- `POST /api/v1/swipes/rewind` — Undo most recent `PASS` (requires `Aura Plus` / `Aura Black` entitlement).
- `POST /api/v1/boosts/activate` — Activate a 30-minute or 24-hour discovery boost multiplier.
- `GET /api/v1/matches` & `DELETE /api/v1/matches/{id}` — List active matches or unmatch.

### 3.5 Real-Time Chat & WebSocket Protocol (`/api/v1/ws`, `/api/v1/conversations`)
- `GET /api/v1/ws` — Upgrades HTTP connection to WebSocket (`WSS`).
  - **Inbound Frames**: `message.send`, `typing.start`, `typing.stop`, `message.read`.
  - **Outbound Frames**: `message.new`, `message.delivered`, `message.read`, `match.created`, `media.ready`.
- `GET /api/v1/conversations` — Paginated list of active match threads with last message preview.
- `GET /api/v1/conversations/{id}/messages?before_id=...&limit=50` — Cursor-paginated message history.
- `POST /api/v1/conversations/{id}/messages` — REST fallback for sending text or approved `media_asset_id`.

### 3.6 Subscriptions, Billing & Webhooks (`/api/v1/billing`, `/api/v1/webhooks`)
- `GET /api/v1/billing/plans` — Public localized pricing plans and feature matrices.
- `POST /api/v1/billing/checkout/stripe` — Creates Stripe Checkout Session with `client_reference_id` and affiliate attribution metadata.
- `POST /api/v1/billing/receipt/apple` — Validates App Store StoreKit 2 JWS transaction payload.
- `POST /api/v1/billing/receipt/google` — Validates Google Play purchase token.
- `POST /api/v1/webhooks/stripe`, `POST /api/v1/webhooks/apple`, `POST /api/v1/webhooks/google` — Cryptographically verified webhook receivers.

### 3.7 Affiliate Attribution, Commissions & Payouts (`/api/v1/affiliates`)
- `POST /api/v1/affiliates/track-click` — Records referral click and returns signed attribution token.
- `GET /api/v1/affiliates/me/summary` — Returns click count, conversions, pending escrow balance, and available payout balance.
- `GET /api/v1/affiliates/me/ledger` — Paginated double-entry commission journal entries (accruals, recurring renewals, refund reversals, payouts).
- `POST /api/v1/affiliates/me/payout-requests` — Requests payout of cleared available balance.

### 3.8 Trust, Safety & Admin Moderation (`/api/v1/reports`, `/api/v1/admin`)
- `POST /api/v1/blocks` & `POST /api/v1/reports` — Block user or submit abuse report with attached message/media evidence.
- `GET /api/v1/admin/moderation/cases` & `POST /api/v1/admin/moderation/cases/{id}/resolve` — RBAC-protected Trust & Safety adjudication.
