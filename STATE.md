# Aura Platform State

* **Media Automatic Retention Reaper**: Implemented background retention reaper with configurable interval (`MEDIA_RETENTION_INTERVAL`) and atomic concurrency guard (`retentionRunning.CompareAndSwap`) preventing overlapping runs; reuses `OriginalPurgeAfter` to automatically identify and safely purge expired assets (especially `SELFIE_VERIFICATION` uploads).
* **Crash-Safe & Consistent Storage Purge**: Updated `DeleteAsset()` and `PurgeExpiredAssets()` to clean physical filesystem files (quarantine + all derivative variants/directories) first; propagates errors and strictly refuses to mark database status `PURGED` if filesystem cleanup fails, ensuring retries remain safe and idempotent.
* **Profile Gallery Preservation**: Enforced strict guard restricting retention purge to non-profile-gallery assets (`purpose <> 'PROFILE_GALLERY'`); profile photos are preserved regardless of retention expiration deadlines; structured logging tracks counts and errors only without exposing selfie payloads or signed URLs.
* **Reachable Android Reset Password Landing Page & Web Fallback**: Replaced inaccessible `localhost:3000` default with LAN endpoint (`http://192.168.29.15:8080/auth/reset-password`); built responsive luxury Aura web page providing both 1-click mobile app launch (`exp://192.168.29.15:8081/--/reset-password?token=...` / `aura://reset-password?token=...`) and an in-browser password reset form with live password policy checklist.
* **Mobile Deep Link Synchronization & Navigation Guard Exemption**: Updated `reset-password.tsx` to automatically populate tokens from both `expo-router` params and `Linking` events on cold/warm starts; exempted `reset-password` in `NavigationGuard` to ensure users with active sessions are not redirected away when tapping recovery links.
* **Discovery Feed Age Assurance Gating**: Allowed completed accounts with pending age verification to browse a limited (up to 10), privacy-safe Discovery feed of eligible public profiles and pass without blocking screens, while strictly disabling likes, super sparks, matching, and messaging until 18+ verification is approved.
* **Photo Upload Confirmation & Immediate Gallery Refresh**: Fixed profile photo upload by requiring `READY` status confirmation before reporting success, preventing false success on polling timeouts, adding automatic on-mount profile and gallery refresh in the profile tab, and introducing profile/preference self-healing on the backend.
* **Resilient Discovery & Matchmaking Database Queries**: Replaced strict `JOIN dating_preferences` with `LEFT JOIN` and `COALESCE` fallback defaults across Postgres candidate search and count queries, resolving regressions where missing dating preferences rows excluded candidates from discovery feeds.
* **Continuous Discovery Keyset Streaming**: Implemented keyset and offset cursor pagination in `GetCandidates` (`repository.go`), emitting deterministic base64 `next_cursor` tokens across batches. Updated `index.tsx` to maintain `nextCursorRef`, prefetch continuous batches, and retain loading state during replenishment rather than dropping into `DealbreakerEmptyState` prematurely, successfully streaming all 4,978+ seed candidates.
* **Search Profile Navigation & Public Detail Screen**: Added full touch target to candidate cards in `search.tsx`, implemented dedicated `profile/[id].tsx` with photo carousel, tags, bio, safe back navigation preserving search queries, and registered the route in `_layout.tsx`.
* **Authorized & Privacy-Sanitized Public Profile Endpoint**: Mounted `GET /api/v1/profiles/{id}` under `communityMw` returning public profile data, badges, and approved gallery photos while strictly excluding private emails, phone numbers, exact coordinates, and selfie media.
